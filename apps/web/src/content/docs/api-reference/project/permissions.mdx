Permission checking and inheritance rule management

## Check a single permission

<Endpoint method="POST" path="/api/permissions/check" />

Resolves whether a Discord member holds a specific permission in a given server. Permissions are derived from their roles and any configured inheritance rules.

**Authentication:** Project API key (`X-API-Key` header)

**Request body** (JSON, required): [CheckPermissionDto schema](#checkpermissiondto-schema).

**Responses**

| Status | Description | Body |
| --- | --- | --- |
| `200` | Permission check result returned. |  |
| `400` | Invalid request body. |  |
| `401` | Valid API key required. |  |
| `403` | Server is disabled or project has no access. |  |

## Check multiple permissions (batch)

<Endpoint method="POST" path="/api/permissions/check-batch" />

Checks a list of permissions for a member in one call. Set `mode` to `ALL` to require every permission, or `ANY` to pass if at least one matches.

**Authentication:** Project API key (`X-API-Key` header)

## Get full resolved permissions for a member

<Endpoint method="GET" path="/api/permissions/{serverId}/{discordId}" />

Returns every effective permission the member holds in the server, including permissions inherited via role hierarchy rules. Requires the `check_permissions` scope for this server.

**Authentication:** Project API key (`X-API-Key` header)
